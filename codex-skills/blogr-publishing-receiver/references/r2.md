# Cloudflare R2 Image Storage

## Durable Storage Model

Treat every Blogr image URL as temporary, untrusted input. Copy the top-level `image_url`, Markdown images in both body fields, and frontmatter `featureImage` before saving the article.

An empty top-level `image_url` is a valid no-feature-image value from Blogr. Skip its download and keep the saved feature image absent; continue processing body/frontmatter images normally.

Persist one of:

- the R2 object key plus a stable same-origin serving route
- an explicitly configured permanent public/custom-domain URL

Do not persist a presigned URL as the durable article value because it expires. For a private bucket, generate a fresh short-lived signed redirect when the stable route is requested, or stream the allowed published object through that route. Restrict the route to keys referenced by published articles; it must not become an arbitrary bucket browser. See Cloudflare's [presigned URL behavior](https://developers.cloudflare.com/r2/api/s3/presigned-urls/).

Do not cache a signed redirect beyond its signature lifetime; a `no-store` redirect is the simplest safe default. When repairing an expired stored target URL, recover a verified target-owned key from existing records and rewrite the stable reference. If the source URL itself expired before copying, request fresh source media or republishing; do not save a broken link or weaken signature checks.

## Credentials And Env Names

Cloudflare creates an S3-compatible access-key pair through its R2 API-token interface; see [R2 authentication](https://developers.cloudflare.com/r2/api/tokens/) and [AWS SDK v3 setup](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/). The runtime needs the access key ID and secret access key, not necessarily an env var named `R2_TOKEN`.

Preserve the target app's existing names. These are documented defaults, not a rename requirement:

```bash
R2_ACCESS_KEY_ID=<access-key-id>
R2_SECRET_ACCESS_KEY=<secret-access-key>
R2_ENDPOINT=<account-r2-endpoint>
R2_BUCKET=<bucket-name>
```

If the target already uses `R2_BUCKET_NAME` or another clear equivalent, reuse it. Do not require a public bucket, custom domain, or `R2_PUBLIC_URL` for the private-route path. Bucket setup is documented in [Create an R2 bucket](https://developers.cloudflare.com/r2/buckets/create-buckets/).

## Safe Remote Download

Apply the [OWASP SSRF prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). Prefer an explicit trusted-source hostname allowlist. If target requirements need broader public URLs, use a validated public-address egress strategy that:

- allows only `https` unless the user explicitly needs `http`
- rejects URL credentials, malformed hosts, unexpected ports, fragments where inappropriate, and non-allowlisted destinations
- resolves and rejects loopback, private, link-local, carrier-grade NAT, multicast, reserved, and metadata-service IP ranges for IPv4 and IPv6
- binds the actual connection to a validated address while retaining the original hostname for TLS/SNI, or uses a trusted egress layer that enforces this; a DNS check followed by an unrestricted second lookup is vulnerable to rebinding
- disables automatic redirects or validates the scheme, hostname, resolved addresses, and port again on every bounded redirect
- applies connection and total timeouts
- caps response bytes while streaming, even when `Content-Length` is absent or false
- checks a strict raster image MIME allowlist and verifies enough file signature data to avoid trusting headers alone
- rejects SVG by default because it can contain active content; add a dedicated sanitizer and serving policy only if SVG is explicitly required

Deduplicate source URLs within a request. Bound image count and media concurrency so the full webhook remains inside Blogr's 15-second response window.

## Object Ownership And Cleanup

Use collision-resistant request-owned keys or a reservation that records whether this request created the object. Do not overwrite a shared key and later treat it as request-owned.

After an upload/rewrite failure or a confirmed database rejection, delete only keys proven to have been created by that request. On a timeout or lost database response, retain uploads until an authorized operation/reservation check resolves whether the mutation committed; a network failure is not proof of rollback. Cache-refresh errors after commit must never trigger deletion. Cleanup is best effort and should be tracked without exposing secrets. Never delete a pre-existing object merely because its source URL appeared in the rejected request.

Rewrite all saved body/frontmatter/top-level references to stable target-owned routes or keys. Assert that no Blogr source URL or presigned target URL is persisted as the durable value.
