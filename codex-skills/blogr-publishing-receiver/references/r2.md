# Cloudflare R2 Image Storage

## Purpose

Blogr image URLs are source URLs for ingestion. They can be signed and temporary. The target app must copy every required image into its own durable R2 storage before saving or rendering the article.

## Required Images

Collect and copy:

- top-level `image_url`
- markdown image URLs in `content_mdx`
- markdown image URLs in `content_markdown`
- frontmatter `featureImage` when present

After upload, rewrite `image_url`, frontmatter `featureImage`, and every markdown image URL in the saved body to the target-owned R2 URL, signed serving URL, private image route URL, or object key used by the target app.

## Env Vars

Use S3-compatible R2 credentials:

```bash
R2_ACCESS_KEY_ID=<access-key-id>
R2_SECRET_ACCESS_KEY=<secret-access-key>
R2_ENDPOINT=<account-r2-endpoint>
R2_BUCKET=<bucket-name>
```

Do not require `R2_TOKEN`, `R2_PUBLIC_URL`, a custom domain, public bucket access, or whole-bucket public access for the default path.

## Safe Download Rules

The server-side downloader must:

- allow only `http` and `https`
- reject empty or malformed URLs
- set a timeout
- enforce a reasonable maximum file size
- verify image content types
- preserve or infer a safe extension
- fail with a clear `400` when a required image cannot be copied

Tests should mock downloads and assert content type and body size behavior.

## Helper Files

Use existing target app helpers first. When none exist, keep helpers focused:

- `createBlogPublisherR2Client.ts`
- `downloadBlogPublisherImage.ts`
- `buildBlogPublisherR2Key.ts`
- `putBlogPublisherR2Object.ts`
- `getBlogPublisherImageUrl.ts`
- `collectBlogPublisherImageUrls.ts`
- `rewriteBlogPublisherImageUrls.ts`

Do not combine unrelated download, upload, rewrite, and validation behavior in one file unless the target app's established pattern requires it.
